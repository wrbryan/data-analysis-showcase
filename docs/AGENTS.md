# Working Rules

Before coding, state the business question, decision owner, data grain, and the smallest useful output.

Prefer the smallest clear solution. Reuse existing project patterns only when they fit.

Use synthetic, public, anonymized, or authorized data only. Never use employer, client, confidential, personal, or secret data.

Show the result in plain English before expanding the project:
- What happened?
- What needs attention?
- What should the owner do next?

Use a branch and pull request for material changes. Do not merge without approval.

Stop when the project answers the business question clearly.
